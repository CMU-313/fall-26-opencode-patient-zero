  What the test does:
  - Inputs: it uses the file's existing invalidSteps generator: 0 and negative
    numbers, fractions, NaN, ±Infinity, any string (including "five", "3" and
    ""), null, and booleans.
  - How it loads them: a small helper, toYamlScalar, writes each value into an
    agent .md file the way a user would type it. NaN and the infinities use
    YAML's own spellings (.nan, .inf), and strings are quoted so "3" stays text
    instead of becoming a number. The file is then loaded through the real
    ConfigAgentPlugin next to a valid agent with steps: 3.
  - Checks, over 40 runs:
    - the invalid agent isn't loaded;
    - a warning is logged that names both the agent and the steps field;
    - the valid agent still loads with steps === 3, so one bad file doesn't stop
      the others loading.

  It sits next to the existing R2 tests: the schema-only test, and the Markdown
  test, which uses YAML values written by hand. The new test covers more invalid
  values than the Markdown test.
